# Gmail outbox guard (T-023, Codex half)

`pipeline.outbox.dispatch` can create a Gmail draft at autonomy level 2, or make a send attempt at level 3 only when `send_emails: auto`. It is not scheduled or wired to a message generator. The checked-in settings say `send_emails: never` and leave `vault.applications_email` empty, so no live Gmail write is currently possible.

Before either action it checks: an applications sender is configured; the matching Google account has `gmail.modify` consent; the OAuth profile is that sender; the recipient is a tracker contact for the same company; the application has a posting and is not terminal; the email is a `kind: email` file in that application's `final/` directory; its drafting mode matches the application; its claim citations, tone and subject pass deterministic checks; and CareerOS is not paused. A proofread-only or outline-only employer also requires `generated_by: ali`. Sending reserves a tracker row before the API call, counts pending/uncertain attempts towards `daily_emails`, and never retries an ambiguous outcome automatically. The tracker records recipient, contact, application and posting, but not message text. No attachments, Cc or Bcc are supported.

`python -m pipeline.outbox status` reports only configuration and consent presence. After the candidate deliberately sets `vault.applications_email`, `python -m pipeline.outbox auth` opens Google's consent for that account. the candidate completes it personally. If it is also the inbox account, the request retains Gmail and Calendar scopes; if it is separate, only `gmail.modify` is requested. Do not run auth or alter `settings.yaml` as part of tests. The existing 2026-09-23 personal token has read-only Gmail consent and does not qualify.

The Gmail API accepts a base64url-encoded RFC 2822 message for [`users.messages.send`](https://developers.google.com/workspace/gmail/api/reference/rest/v1/users.messages/send) and a `message.raw` object for [`users.drafts.create`](https://developers.google.com/workspace/gmail/api/reference/rest/v1/users.drafts/create); both accept `gmail.modify` (retrieved 2026-09-24). Tests use a fake client and a temporary SQLite database; they never contact Google. LinkedIn actions and the end-to-end day's acceptance remain for Claude.
